# C2 화면 설계와 표시 원칙

운영자가 Alert를 찾고 사유와 근거를 읽는 조회 화면이다. 차콜 배경, 구분선과 여백으로 정보의 우선순위를 표현한다. 실행·검증은 [README.md](README.md), 데이터 형식과 조회 조건은 [API 계약](../docs/api-contract.md)을 참조한다.

## 데이터 표시

| 항목 | 원칙 |
|---|---|
| `level` | 서버의 `INFO`·`WARN`·`CRITICAL`을 그대로 표시한다. INFO는 안전 보장이 아니다. |
| `human_required` | 수준과 독립적으로 ‘검토 필요’ 또는 ‘검토 요구 없음’을 표시한다. 검토 요구 없음은 안전·처리 완료를 뜻하지 않는다. |
| 위험·불확실성 점수 | 범주별 정수 합계를 따로 표시한다. 재계산하거나 확률·백분율·게이지로 바꾸지 않는다. |
| 사유 | 정의된 규칙·근거 조합에만 한국어 설명을 적용하고, 그 밖에는 서버 원문을 표시한다. 원문 펼치기에 `reason_summary`와 `signal.reason`을 보존한다. |
| 신호·근거 | 규칙, 범주, 사유, evidence, 신호 점수와 override 여부를 구분한다. GET에 없는 metadata 열람 기능은 제공하지 않는다. |
| 권장 조치 | 응답 순서대로 한국어 조치명과 원문 코드를 표시하는 읽기 전용 목록이다. |
| 추적 정보 | `event_id`, `alert_id`, 생성 시각 KST, 생성 요청의 `trace_id`를 표시한다. 조회 응답의 `X-Trace-ID`와 구분한다. |

실패 신호는 입력된 실패 코드의 보고값이며 모니터 서비스가 직접 관측한 장애로 설명하지 않는다. `latency_ms`도 입력된 지연 시간이며 API 처리 시간이 아니다. 실패 신호는 위험 점수에 합산되지 않으며 override로 점수와 관계없이 CRITICAL이 될 수 있다. 정확한 사유 매핑은 [display-contract.mjs](src/display-contract.mjs)의 `signalReason`·`summaryFor`에서 관리한다.

`null`은 ‘입력값 없음’과 원래 값을 함께 표시한다. `0`, `false`, 빈 문자열은 누락으로 취급하지 않는다. evidence의 JSON 자료형과 빈 신호·근거·권장 조치 상태를 보존하고, 필수 응답값 누락을 기본값으로 숨기지 않는다. 동적 문자열은 HTML 본문·속성에서 이스케이프하며 인라인 JSON도 HTML 종료 문자에 안전하게 삽입한다.

## 보기와 정보 배치

| 보기 | 배치 |
|---|---|
| 탐색 | 목록을 전체 폭으로 표시 |
| 조사 | 목록과 상세를 나란히 표시하고, 좁은 화면에서는 세로 배치 |
| 집중 읽기 | 조회 도구와 목록을 숨기고 상세를 최대 820px 폭으로 표시 |

상세는 평가 사유 → 수준·검토 여부 → 점수 → 신호와 근거 → 권장 조치 → 추적 정보 순서로 읽는다. 보기 전환은 재조회하지 않으며 입력값·적용 조건·누적 목록·커서·현재 상세·원문 펼치기를 보존한다. 탐색에서 상세를 열거나 유효한 ID를 조회하면 조사로 전환하고, 집중 읽기에서 닫으면 조사로 돌아간다.

목록 사유는 3줄, `event_id`는 2줄로 미리보기한다. 데이터 자체는 자르지 않으며 상세에서는 긴 한글과 공백 없는 식별자·원문·근거를 끝까지 읽을 수 있어야 한다.

## 조회와 상태 유지

- **조건 적용:** 개수(기본 5, 요청당 1~100), 수준, 검토 여부, KST 시작·종료, 정렬을 조회 버튼 또는 Enter로 함께 적용한다. 편집 중 값(`draft`)과 적용된 조건(`query`)을 구분하며, 입력 변경만으로 요청하지 않는다. 잘못된 입력은 자동 보정하지 않고 현재 결과를 유지한다.
- **필터 초기화:** 수준·검토·시작·종료 입력만 비운다. 개수·정렬·ID 입력과 결과는 유지하며 다음 조회로 적용한다. 같은 조건을 다시 제출해도 첫 페이지부터 조회한다.
- **시각과 순서:** 날짜는 Alert 저장 시각이며 `시작 ≤ 저장 시각 < 종료`로 조회한다. 한쪽 경계만 입력할 수 있고 기본 기간은 없다. 기본 정렬은 최신순이며 서버의 시각·ID 순서를 그대로 따른다.
- **더보기:** 적용된 조건과 서버 `next_cursor`를 사용한다. 로딩·실패 중 목록·상세·커서를 유지하고 수동 재시도를 제공한다. 응답의 중복·순서·커서 오류는 부분 반영하지 않는다. null 커서이면 추가 요청하지 않는다.
- **건수:** API `count`는 이번 페이지, ‘현재 불러온 N건’은 누적 건수다. 전체 DB 건수나 총 페이지로 표현하지 않는다. 요청당 100건은 누적 제한이 아니다. 커서 조회는 고정 스냅샷이 아니므로 최신 첫 페이지는 새 조회로 확인한다.
- **상세 조회:** 목록 선택 상세는 새 목록 조회 시 비우고 같은 ID가 새 첫 페이지에 있을 때만 다시 조회한다. ID 직접 조회는 양의 안전한 정수를 검증한 뒤 목록과 독립적으로 유지한다. 재시도는 마지막 요청 ID·조회 경로를 사용한다. 닫기·새 요청 이후의 늦은 응답은 무시한다.

## 로딩과 오류

| 상태 | 안내 |
|---|---|
| 로딩 | Alert를 불러오는 중입니다. |
| 성공한 빈 목록 | 현재 조회 조건에 맞는 Alert가 없습니다. |
| 상세 404 | 해당 Alert를 찾을 수 없습니다. |
| 요청 실패 | Alert를 불러오지 못했습니다. |
| JSON·필수 응답값 오류 | 응답 데이터를 확인할 수 없습니다. |

더보기 상태는 목록 하단에 별도로 표시한다. API와 mock은 같은 응답 검증·상태·렌더링을 사용하며, API 오류를 예시 데이터로 대체하지 않는다.

## 시각 규칙과 접근성

색상·크기·반응형 수치의 기준은 [styles.css](src/styles.css)다. 주요 색상은 다음과 같다.

| 역할 | 색상 |
|---|---|
| 배경 / 표면 / 근거 영역 | `#191E23` / `#20262C` / `#1B2026` |
| 본문 / 보조 글자 | `#EDF0F3` / `#AEB7C0` |
| 구분선 / 입력 테두리 | `#39424C` / `#697986` |
| 선택 배경 / 인터랙션 | `#263338` / `#83B7B0` |
| CRITICAL / WARN | `#F3A59D` / `#E7C486` |

- 한국어는 Pretendard, 영문은 Geist, 코드·식별자는 Geist Mono를 사용한다. 색상만으로 의미를 전달하지 않고 문자·아이콘·선택선·`aria-current`를 함께 사용한다.
- 조사 보기는 960px 이하에서 한 열로, 목록 행은 640px 이하에서 정보 블록으로 바뀐다. 점수와 권장 조치는 평면적인 행·목록으로 구성한다.
- 폼과 기존 목록 DOM을 유지해 편집 위치와 포커스를 보존한다. 명시적 상세 열기·재시도는 상세 제목으로 포커스를 옮기고, 응답 도착이나 자동 선택 복원은 포커스를 옮기지 않는다. 닫기는 원래 목록 버튼·ID 입력으로, 해당 요소가 없으면 보이는 목록 제목으로 돌아간다.
- native form·label, 의미 있는 제목, 오류 연결, 키보드 포커스 표시와 reduced-motion을 유지한다. 더보기는 로딩 중에도 버튼을 유지하고 `aria-disabled`와 controller로 중복 요청을 막는다. 마지막 페이지에서 포커스된 버튼이 사라지면 목록 제목으로 이동한다.
- 600px 넘게 스크롤하면 ‘맨 위로’를 표시한다. 버튼은 상단 제목으로 포커스와 스크롤을 즉시 이동하며 조회 상태는 유지한다.

가상 승인·처리 완료·일괄 조치, 실시간 상태나 성능 차트, 전체 통계 카드, 장식용 내비게이션은 추가하지 않는다. 화면 변경 시에는 WARN과 검토 요구 없음의 조합, 긴 원문, 좁은 화면·200% 확대, 키보드 이동, 오류·재시도·늦은 응답을 확인한다.
